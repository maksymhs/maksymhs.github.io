Spring AI 2.1 milestone: tool calls and reasoning become typed message parts

13 Oct 2026 · 2 picks

Agent code lives or dies on how it replays model output between turns. Spring AI 2.1.0-M1 changes the message model for that, and fixes a silent timeout bug.

  1. Spring AI 2.1.0-M1 Available Now

    Spring Blog · 25 Sept 2026

    The first milestone of Spring AI 2.1 moves the baseline to Spring Boot 4.2 and changes how messages are modelled. AssistantMessage, UserMessage and ToolResponseMessage now hold an ordered list of parts: text, reasoning, tool calls, tool results, media, and an UnknownPart that keeps the raw JSON of blocks an adapter does not understand yet. Reasoning and tool-call parts can carry an opaque payload that must be replayed unchanged, such as Anthropic thinking signatures. The post says only the new OpenAI Responses chat model uses parts natively for now; the other models are planned for 2.1.0-RC1. It also lists a fix I find telling: since 2.0.1 a hardcoded 60-second per-call timeout overrode the configured one and aborted longer streams. Why it matters: agent loops fail at the seams, when state is replayed between turns. In my work on an MCP server and agents for internal tooling at Openbank, that is where the bugs hide, so a typed, lossless message model is the right direction. It is a milestone, so I would try it in a branch, not in production.

  2. When failover isn't safe: Building high-availability PostgreSQL on Kubernetes

    Datadog Engineering · 4 Jun 2026

    Datadog describes a simulated zonal failure where asynchronous replicas lagged too far for Patroni to promote any of them. Their fix is synchronous standbys as the only failover candidates, with async read replicas. Worth reading for the failure scenarios and the benchmark numbers on synchronous_commit modes; an older post, but a good companion to a zone drill.
