JEP 543 makes structured concurrency final in JDK 28

22 Oct 2026 · 3 picks

After seven preview rounds, structured concurrency is final in JDK 28, with no API changes from the last preview. Fan-out code in Java backends gets a lifetime you can read in the code.

  1. JEP 543 Finalizes Structured Concurrency in JDK 28, Ending Seven Preview Rounds

    InfoQ · 19 Oct 2026

    JEP 543 makes StructuredTaskScope final in JDK 28 after seven preview rounds, which InfoQ calls the longest preview cycle of any Project Loom feature. The API is unchanged from the seventh preview in JDK 27, so migrating means recompiling without --enable-preview. The model is the point: the thread that opens a scope forks subtasks, joins in one place and closes the scope, which cancels whatever is still running. Joiner policies cover the usual cases, such as waiting for every result, taking the first success or stopping at the first failure. For backend code that fans out to several upstream systems, like the aggregation endpoints I worked on at Simyo, that replaces hand-written cancellation and leaked threads with a lifetime you can see. Two things I would check before adopting it: JDK 28 reaches general availability in March 2027, according to the article, and the API does not yet promise which failure join() reports when several subtasks fail at once.

  2. Article: Distributed Spring Batch Without a Message Broker

    InfoQ · 21 Oct 2026

    The author uses the shared database as the only coordination layer for Spring Batch partitioning, with heartbeats and compare-and-set updates, aimed at roughly 2 to 20 nodes. It saves running a broker for batch fan-out, but reassigned partitions run at least once, so steps must be idempotent. The article gives no benchmarks and describes the author's own framework, so I would read it as a design to learn from.

  3. Netflix Bridges AWS IAM and Internal Identity with Workload Attestation

    InfoQ · 21 Oct 2026

    Spark jobs on EMR trade their AWS execution identity for a short-lived internal certificate. The driver attests once and hands credentials to the executors, which the article notes makes the driver a trust boundary. No latency or certificate lifetimes are given. Worth watching if you bridge IAM roles with an internal PKI.
