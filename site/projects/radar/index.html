CASE STUDY / AUTOMATION & WRITING

Engineering Radar

A publishing pipeline that separates source facts from AI-assisted commentary.

View source Read the radar
  • Node.js
  • RSS
  • GitHub Actions
  • LLMs

The context

Following AI and backend engineering creates a steady stream of articles. Radar collects feeds, selects candidates and produces a short daily digest with original takes. The public site discloses that the commentary is drafted with AI assistance.

Decisions & tradeoffs

Keep source metadata out of generation

Links, titles, sources and dates come from feeds. The model writes the headline, introduction and commentary, rather than inventing source metadata.

Validate before publishing

The pipeline reads the selected articles and validates the draft before passing it to the renderer. The numeric checks are useful guardrails, not a substitute for human fact-checking.

Publish static artifacts

Node.js renders the post, archive, RSS and sitemap. GitHub Actions runs the daily pipeline and triggers the existing Pages deployment. The workflow can report its outcome through the Worker.

How it fits together

  1. RSS candidates
  2. Article text + draft
  3. Validation
  4. Static pages + RSS

The daily GitHub Actions workflow orchestrates this pipeline; the Worker provides the LLM endpoint.

A repeatable publishing workflow.

  • A public archive, individual post pages and an RSS feed generated from the same post data.
  • Daily automation with validation and links back to original sources; AI assistance is disclosed to readers.
  • No readership or time-saving metrics are claimed. Source quality and editorial accuracy remain ongoing concerns.
